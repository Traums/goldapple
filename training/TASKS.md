# Задания. Золотое яблоко

Изучай запущенный сервис: код, базу данных, Swagger и ответы API.
Готовые ответы, формулировки требований и диаграммы в этот файл не включены.
Результат каждого раздела оформи отдельно.

## 1. Исследование системы

По результатам изучения системы подготовь описание:

1. Кто основные участники системы.
2. Для чего нужен сервис.
3. Какие основные бизнес-сущности в нём есть и как они связаны.
4. Какие сценарии уже реализованы.
5. Какие граничные случаи видны в поведении системы.

## 2. Требования

Бизнес-запрос:

«Магазин косметики хочет дать клиентам возможность самостоятельно собирать и оформлять заказ в мобильном приложении.»

На основе запроса и изучения сервиса самостоятельно подготовь:

1. Список вопросов заказчику.
2. Функциональные требования.
3. Нефункциональные требования.
4. Бизнес-правила.
5. Ограничения.
6. Acceptance Criteria.

## 3. BPMN

Нарисуй процесс создания заказа.

В процессе должны быть отдельные ветки:

- успешное создание;
- клиент заблокирован;
- товар снят с продажи;
- товара нет в наличии;
- на складе не хватает количества;
- произошла техническая ошибка.

Диаграмму нужно создать самостоятельно.

## 4. UML

Создай UML Sequence Diagram для создания заказа.
Диаграмму нужно создать самостоятельно.

## 5. Database

Выполни SQL-запросы к базе сервиса. Решения в файл не записывай, запросы напиши сама.
Иди от простых запросов к более сложным.

1. Получи всех клиентов.
2. Найди клиента по фамилии.
3. Получи все товары со статусом ACTIVE.
4. Получи товары конкретной категории.
5. Выведи товары, отсортированные по цене.
6. Получи заказы конкретного клиента.
7. Получи только оплаченные заказы.
8. Найди самый дорогой товар.
9. Посчитай количество заказов у каждого клиента.
10. Посчитай сумму заказов по каждому статусу.
11. Соедини заказы и клиентов и выведи имя, фамилию и сумму заказа.
12. Соедини позиции заказа и товары и выведи название товара, количество и цену.
13. Найди клиентов, у которых нет ни одного заказа.
14. Посчитай количество товаров в разрезе категории и статуса.
15. Для каждого товара покажи суммарное проданное количество, включая товары, которых нет ни в одном заказе.

## 6. REST API

По каждому endpoint сервиса определи и опиши:

1. Назначение.
2. HTTP-метод.
3. Параметры и тело запроса.
4. Тело успешного ответа.
5. Возможные ошибки: HTTP-статус и код ошибки.

Отдельно ответь на вопросы:

1. Чем PUT отличается от PATCH.
2. Почему каталог и чтение заказа вызываются методом GET.
3. Почему создание заказа и проверка заказа вызываются методом POST.
4. Почему отмена заказа вызывается методом POST, а не DELETE.

## 7. Postman

Собери коллекцию запросов и для каждого вызова зафиксируй HTTP-статус и тело ответа.

1. Получи каталог товаров.
2. Получи заказы клиента.
3. Успешно создай заказ и повторным запросом прочитай его.
4. Создай заказ для заблокированного клиента.
5. Добавь в заказ товар, которого нет в наличии.
6. Закажи больше, чем есть на складе.
7. Запроси заказ с несуществующим идентификатором.
8. Проверь заказ, который сервис разрешает оформить.
9. Проверь заказ, который сервис оформить не разрешает.
10. Отмени заказ, который ещё можно отменить.
11. Отмени заказ, который отменить уже нельзя.

Идентификаторы и количества возьми из данных сервиса.

## 8. Финальная задача

Новый запрос бизнеса:

«Бизнес хочет добавить промокод: скидку в процентах, которая действует с startDateTime до endDateTime.»

Этой возможности в текущем сервисе нет. Готовой модели, API и диаграмм по ней в репозитории нет: их нужно спроектировать.

Подготовь:

1. Требования к промокоду.
2. Вопросы заказчику.
3. Изменение модели данных.
4. Описание API.
5. BPMN процесса.
6. Sequence Diagram.
7. Список ошибок.
8. Acceptance Criteria.
9. Задачи разработчику.

Код сервиса в рамках этого задания менять не нужно.
